# 逆向还原五步分析法

拿到参考图后，生成 HTML 前必须按此顺序完成系统分析（在 thinking 中完成即可，不必全部写给用户）：

## 第 0 步：先定输入（动手前必做，这步的结论要写给用户看）

**0a · 版权切分——只学"设计语法"，不搬"版权内容"**

把图中元素分成两栏，绝不混淆：

| 学（照搬） | 换（绝不进成品） |
|---|---|
| 版式骨架、分区比例、对齐方式 | 别人的**署名 / handle / 水印**（如 `@某人`） |
| 字体气质、字号字距、层级关系 | 别人的**原文案**（标题、slogan、引文） |
| 配色、圆角、装饰手法（条形码、分割线…） | 别人的**照片 / 插画 / logo / 吉祥物** |

即使用户说"原样还原"，署名和图源默认也要替换成中性占位符——
"还原"指的是**版式还原**，不是把别人的署名烤进用户的成品。这条不需要用户提醒，默认执行。

替换时**占位词字数要对齐原词**（`GOALS` 5 字母 → `TITLE` 5 字母），
这样排版效果和参考图一致，用户也知道自己的文案该控制在几个字。

**0b · 目标平台、文案与语言**

- **目标平台/尺寸**：用户没指定平台时**必须先问**（小红书 / 公众号 / B站 / 方图 / 视频…，见 sizes.md），
  **不默认小红书**——尺寸选错整张白做。这是唯一"宁可问也别猜"的项，但要和下面问文案的那句**合并成一句问**。
- 用户**给了文案** → 直接按文案语言选字体（见 fonts.md 第一原则），**不要多问一轮**
- 用户**没给文案**（要的是排版母版）→ 出**双语就绪**的母版：字体降级链 + 面板中/英预设开关，**同样不问**
- **中/英预设开关是面板的固定必有项**（不论给不给文案、给的什么语言都要有，见 control-panel.md 第一层），选字体只是决定"初始停在哪个预设"
- 真要问，就把"平台 + 文案"并进同一句里顺带问，不单独加一轮提问

> 原则：**能用默认值和开关解决的，别用提问解决；但目标尺寸例外——必须先确认，只是要合并进同一句问。**

## 五步分析

1. **整体结构与布局分析**：画布如何分区？主视觉、标题、辅助信息各占什么位置？对齐方式（居中/左对齐/对角）？留白比例？
2. **视觉设计系统分析**：提取配色（背景、主文字、强调色、辅助色，用 hex）；识别字体——先定大类（衬线/无衬线/楷体/手写/艺术体），再看细节：字重（细/中/粗）、字宽（扁/正/长）、笔画硬软、字距疏密，然后按 fonts.md 的"匹配方法"选一款并规划 CSS 微调；圆角、边框、阴影的统一规律。
3. **组件与元素分析**：逐个清点图中元素——标签、贴纸、图标、装饰线、照片、插画。**绝对不要遗漏原图中的主要图案元素**。
4. **技术实现策略**：每个元素用什么实现？文字→HTML+CSS；几何装饰→CSS/内联 SVG；质感纹理→layout-tips.md 的 CSS 技巧；照片/插画→`<img>` 占位。
5. **设计意图推断**：这张封面想让读者第一眼看到什么？还原时保持同样的视觉优先级，再把用户的文案按此层级填入。

## 第 6 步：还原度预判（分析完、动手前，把结论写给用户看）

做完第 4 步就知道每个元素靠什么实现，此时给用户一句**诚实的能力交底**——
别闷头开做、做完才发现照片那块是假的。参照第 4 步把元素分三档：

| 档位 | 典型元素 | 处理 |
|---|---|---|
| ✅ HTML/CSS 能 1:1 还原 | 文字排版、纯色/渐变色块、条形码、几何装饰、圆角描边 | 直接做 |
| 🟡 只能近似，需真图 | 真实摄影、树影水波纹理、复杂合成、手绘插画 | 用占位图，明说"这块得你换真图" |
| 🔴 CSS 基本做不到 | 整图依赖某张照片的构图/光影、特殊笔触质感 | 提前说清"还原度到此为止" |

输出一句就够，例如：「版式/文字/条形码能 1:1 还原；中间那张俯拍人流是摄影，我先占位，
**这块的最终效果取决于你换的真图**；预估整体还原度约 8 成。」

好处：用户在投入前就知道哪块要自己补图，而不是拿到成品才发现照片是假的。

## 封面特化要求

- 尺寸按所选预设（见 sizes.md，默认小红书 3:4 1086×1448），按画布比例的方向感构图
- 用户提供的文案是主角：参考图的文字内容全部替换为该文案，只保留其排版角色（哪句是主标题、哪句是副题）
- 文案过长时按视觉层级裁剪，先保主 hook，不要硬塞
